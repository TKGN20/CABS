## 真实数据接入检查

在本机 SPLADE-0.1M 上执行四条固定选择查询，独立生成精确 GT。
每方法一次构建、三轮计时，查询单线程；限制每方法 600 秒及 8 GiB 地址空间。

| 方法 | 四条查询的 Recall@50 | 返回结果审计 |
| --- | ---: | --- |
| CABS | 0.965 | 通过 |
| SOSIA | 0.265 | 通过 |
| 修复版 SINDI | 1.000 | 通过 |
| SEISMIC | 1.000 | 通过 |
| 原始 SINDI 对照 | 1.000 | 通过 |

这里的“通过”指原始 ID、精确得分、排序和计时记录有效，不代表吞吐量优劣或
目标召回已验收。SOSIA 使用较小的接入配置，并非作者默认配置或调优结果；
四方法尚未同召回匹配，不计算加速比。完整配置、原始记录与资源日志见英文
[阶段记录](DELIVERY_CHECKPOINT_20261024.md)。

原始和修复版 SINDI 在这四条真实查询上均返回 1000 个有效候选、Recall=1.0，
因此不能把先前的小型边界失败扩大解释为原版在真实数据上普遍失效。
CABS 此次自动选择 K=1、B=13798、m=167，尚不能据此论证该实例的球面路由收益。
