## 三、路由为什么没有提前终止

本轮重建既有 1M 最终索引，16 条查询产生 128 条路由记录、0 次停止事件；结果和计数均与旧完整记录匹配。前四条查询逐簇穷举，32 个实际最大内积均不超过所用上界。

| 诊断量 | 结果 |
| --- | ---: |
| 覆盖半径范围（弧度） | 1.51586–1.53449 |
| 角度因子最小值 / 中位数 | 0.999028 / 0.999968 |
| 角度因子恰为 1 的比例 | 35.94% |
| suffix 上界 / 当前第 50 名得分，最小 / 中位数 | 4.097 / 5.445 |
| 簇上界 / 实际最大内积，最小 / 中位数（32 项） | 3.326 / 4.360 |

这些记录表明，本实例的较大覆盖半径使角度因子接近 1，几乎不能收紧范数上界；suffix 界仍远高于当前阈值，因而严格停止条件未成立。这是本实例的诊断解释，不是“所有稀疏数据都无法停止”的结论。四组 0.1M 参数试验的平均 probe 数也都等于各自 K，尚无额外真实数据上的提前终止收益证据。

证据：[逐步路由 CSV](../results/engineering/routing_bounds_1m_20261022/routing_bounds.csv)、[复算结果](../results/engineering/routing_bounds_1m_20261022/analysis.json)、[重建等价性](../results/engineering/routing_bounds_1m_20261022/observation.json)。

上界是保守的最大值保证。不能将最大半径换成 95% 分位数后仍宣称原有 safe stopping 成立。合成夹具证明实现能触发终止；真实实例的上界诊断回答的是它为什么没有触发，二者不能相互替代。

这里应区分 routing correctness（按定义路由与安全终止）和 routing selectivity（实际减少访问簇或候选）。现有测试支持前者；32 项穷举检查只是少量真实查询的数值验证，不是所有输入上浮点实现的形式化证明。真实 SPLADE 上提前停止的效率收益仍待验证。

降低 k_max 并未在这里带来更高吞吐量，而且召回下降；增加校准查询数也未呈现单调的效率收益。B 和验证量不能单独预测 QPS：重校准同时改变 K、局部 m 和候选处理。原默认在本组共同查询上吞吐量最高，nc=8/k_max=100 的 Recall 更高，因此不能将四配置概括为同质量下的优劣排序。

建议保留原默认。不能将此 64 查询试验替代既有全查询结果，更不能用它证明跨数据集鲁棒性。

`nc=4, k_max=100` 是当前公开实验协议的固定配置，未被证明是跨 workload 最优设置。后续不能用最终测试集逐数据集挑选参数，再将选出的配置描述为完全自动配置。

证据：[预先登记的范围](../results/engineering/calibration_pilot_20261022/EXPERIMENT_PLAN.md)、[全部配置与共同查询 ID](../results/engineering/calibration_pilot_20261022/comparison.json)、[原始子目录](../results/engineering/calibration_pilot_20261022)。

这不是同 Recall 比较。还没有独立构建方差、多个 seed、1M 参数矩阵或跨编码器结论。改变 k_max 会改变“最大支持结果数”的实验配置；比较时不能同时宣称其他条件及全部工作点不变。

## 六、论文与方法的可行改进方向

现有结果支持保留 Section IV 的机制实现，不支持把所有性能问题归结为“算法没有实现”。可以在结果分析中准确说明：

> Routing prioritizes cluster access and permits early termination when the bounds are sufficiently tight. On the measured SPLADE-1M default realization, all queries visit all eight clusters; this result therefore does not demonstrate an early-termination speedup. Clustering can still affect local hash configuration and candidate generation.

若另行探索更紧的安全上界，可讨论对非负向量保存每簇坐标最大值 u_ij=max(x_j)，并使用 min(U_angular, sum_j q_j u_ij)。该表达式在精确算术下是有效上界，但需要证明数值实现的保守性、计入额外存储/维护成本并实际测试；本轮未实现，也不承诺会提速。

密集坐标最大值存储可能增加 O(Kd) 空间，并引入查询扫描和动态维护成本；更紧的界不必然改善端到端 QPS。该方向不纳入本次生产版本，也不修改已固定的 Section IV。

这类新上界、异常向量单独缓冲或重新定义校准代价，应与当前 PR 的实现整改分开审批。不能用分位数统计静默替代最坏情况条件。
