## 本轮实现

1. 在实验层新增 `experiments/cabs_space.hpp`，导出 CABS 的 29 个分项，涵盖
   对象头、实际分配容量、编码元数据、分区、局部表和保留的校准缓冲。
   原生产函数的九项汇总同时保留，逐项对照，不改冻结实现。
2. 构建输入 `Calibration` 复制进索引后，释放实验驱动中的临时副本；文档
   sketch cache 也在计时查询前释放。两者的释放成本进入构建时间，索引自身
   保留的 calibration 数据照常计入空间。清单明确限于无 owned/delta 行的静态索引。
3. `IT_seconds` 记录加载开始至索引就绪的完整区间，并分列加载、校准 GT、
   原生构建、释放及驱动准备时间。四个主要阶段之和另存于
   `IT_legacy_stage_sum_seconds`，它是本次运行的阶段和，不是旧实验的计时值。
4. 新增 `cost_record.py`，统一输出 IT、索引结构、原始向量和总 IS，绑定输入、
   原始清单与摘要的 SHA-256。序列化字节和进程 RSS 独立保留；有资源日志时
   核对成功退出状态。其状态为 `COST_COMPONENT_RECORD_AUDIT_ONLY`。
5. 共用结果审计会绑定 `index_space.json`；声明已报告空间分项却缺少清单的
   记录会被拒绝。实验配置锁也覆盖新增 CABS 头文件的源码哈希。

全部变化位于实验与证据层。PR #4 的 19 个生产算法／默认配置文件通过冻结
检查，K/m/B 自动规则、默认值和历史测量文件未改动。

## CABS 旧口径与新增分项的对应

在同一组 SPLADE-0.1M 控制中，自动选择仍为 K=1、B=13798、m=167，四条
selection 查询的结果 CSV 与上一轮逐字节一致。独立 GT 也与上一轮一致。

| 项目 | 字节 |
| --- | ---: |
| 旧汇总口径总量 | 191,552,265 |
| 完整 map 节点链接／布局开销补项 | 448 |
| 新增分项总量 | 191,552,713 |

差额来自阶段计时 map 的 14 个节点：当前 libstdc++ 节点为 72 字节，键值
负载为 40 字节，14×(72−40)=448。旧函数的值保存在 `IS_legacy_bytes` 和
`legacy_components_bytes`，历史数字未被覆盖。这是明确的计量补项，不能解释
为算法额外开销突然增加。完整节点核对目前要求已审计的 libstdc++ ABI，其他
标准库不使用猜测值作为后备。

## 四方法固定配置记录

沿用同一 SPLADE-0.1M 输入、四条 selection 查询及各方法接入配置。每方法
一次构建、三轮单线程查询，600 秒及 8 GiB 地址空间限制。配置详见各方法
原始 receipt；这些工作点没有匹配 Recall，不用于性能或空间效率排名。

| 方法 | IT（秒，原始记录） | 索引结构字节 | 原始向量存储字节 | 总 IS 字节 |
| --- | ---: | ---: | ---: | ---: |
| CABS | 347.993087 | 88,913,049 | 102,639,664 | 191,552,713 |
| SOSIA | 1.822853 | 114,976,071 | 102,639,664 | 217,615,735 |
| SINDI | 1.200055 | 211,843,908 | 102,639,664 | 314,483,572 |
| SEISMIC | 123.954234 | 1,633,083,045 | 102,639,640 | 1,735,722,685 |

SINDI 的原生 forward 副本计入结构列；SEISMIC 已在原生 forward store 中
保留完整向量，不能重复相加。SEISMIC 的 CSR 参考文件仍为 102,639,664 字节，
其 heap 不包含该文件的 24 字节头。这些表示差异保留在定义字段内，不静默
修正旧值。SEISMIC 的 energy=1 接入配置保留较大的 summaries；原始成本照报。

CABS 当前 K=1，不能据这次控制宣称球面路由取得效率收益。四条查询也不足以
证明工作负载性能，所有原始 QPS 均保留但不据此计算加速比或替换论文目标。

## 核验范围

- Release 与 Debug＋ASan/UBSan 各七项实验 CTest 通过；这不等于 SINDI 原生库
  已通过完整 sanitizer 检测。
- 保存记录复算通过：39 份收据、22 组合成测试、5 组既有真实方法／对照记录、
  4 组真实空间清单和 12 条统一成本记录。
- 新 CABS 合成清单的 Recall 预期值来自独立 oracle 汇总，避免把驱动浮点
  累加的末位差异误认为记录变化。原始摘要、结果和计时字节均未修改。
- `a1bf4a2` 的五项 GitHub workflow 已全部成功；这是该指定提交的 CI，
  本轮 CABS 变更仍须接受自己提交上的新 CI。

保存记录复算不重新运行全量构建；真实向量得分的独立重算仍需同哈希数据。
当前代码拒绝篡改容量、缺少分项、错误方法及不匹配的成本参数，不把 API 的
零值桩、序列化文件大小或进程 RSS 当成 IS。
